# 基金持仓自算估值 设计文档

- 日期：2026-07-29
- 状态：已通过设计评审，待编写实现计划
- 相关代码：`workflow/fund.py`

## 一、背景与问题

2026-07-21 起，天天基金 `fundgz.1234567.com.cn` JSONP 盘中估值端点 301 下线。项目先后切换至 `FundValuationLast`、再切换至 `FundMNFInfo` + `NAVCHGRT` 兜底（见 `docs/PLAN.md` 第六节更新记录、`README.md` 数据接口节）。

现状：`FundMNFInfo` 对多数基金不再返回盘中估算 `GSZ/GSZZL`（数据侧不再提供），仅能拿到结算后的 `NAVCHGRT`（净值涨跌幅，收盘后才反映当日涨跌）。盘中实时估值已无接口来源。

## 二、目标

**完全替代实时估值**：盘中统一用「基金持仓 + 重仓股实时行情」自算估算净值，不再依赖接口的 `GSZ`。已结算（净值日=今日）仍用 `NAVCHGRT` 真实值，逻辑不变。

**适用范围**：用户持仓基本为 A 股指数/行业基金（持仓稳定、集中度高、调仓少），自算估值准确度高。对主动管理型/债基/QDII 仅作兜底降级处理（非主场景）。

## 三、非目标

- 不追求与原天天基金盘中估值完全一致的精度（其基于全持仓 + 股票仓位，数据来源不可得）。
- 不支持债基/QDII/货基的盘中估算（持仓非 A 股，无法用 A 股行情推算）。
- 不改 `funds.json` 配置格式。
- 不拆分 `fund.py` 为多模块（保持「单文件零依赖」卖点）。

## 四、方案选择

经对比三个口径/复杂度递增方案，选定 **方案 2 · 前十 + 覆盖率缩放**：

| 方案 | 口径 | 复杂度 | 取舍 |
|---|---|---|---|
| 1 轻量前十加权 | `Σ(wᵢ×rᵢ)`，其余按 0 | 最简 | 系统性低估波动，覆盖低者偏差大 |
| **2 前十+缩放（选定）** | `Σ(wᵢ×rᵢ)/cov` 放大到满仓 | 几乎同 1 | 对指数/行业基金最贴合；复杂度无额外负担 |
| 3 全持仓+股票仓位 | 全持仓加权后按股票仓位折算 | 最重 | 全持仓仅半年报/年报披露（更滞后）；资产配置端点待寻；收益不抵复杂度 |

理由：用户持仓基本为指数/行业基金，前十之外多为同行业股票、同向性强，缩放口径最接近真实；复杂度与方案 1 一致，无额外数据源负担；方案 3 精度提升抵不过其复杂度与滞后。

## 五、架构与数据流

持仓估算**只在盘中、未结算时**作为 `gsz` 的来源；已结算用 `NAVCHGRT`，不变。即把 `parse_fund` 盘中分支的输入从接口 `GSZ` 换成自算的 `gsz_est`。

```
读配置 groups
  │
  ├─① FundMNFInfo 批量   -> name / NAV / PDATE / NAVCHGRT / GSZ(兜底) / GZTIME
  │
  ├─② 持仓缓存(本地) 命中?
  │     否 -> fundf10 jjcc 拉<基金>前十大(secid,占净值比) -> 写缓存
  │     是 -> 直接用
  │
  ├─③ 股票行情 push2 ulist.np 批量 -> 所有重仓股(跨基金去重)涨跌幅 f3
  │
  └─④ 估算: gsz_est = NAV × (1 + est%/100)
     喂入 parse_fund 盘中分支(复用现有收益/持有额计算)
```

## 六、组件划分

保持单文件 `workflow/fund.py`，新增三个内部函数（不拆模块，符合既定「单文件零依赖」风格）：

- `fetch_holdings(code)` — 拉取 + 解析 + 缓存前十大重仓股
- `fetch_stock_quotes(secids)` — 批量股票实时行情
- `estimate_gsz(nav, holdings, quotes)` — 估算净值

`fund.py` 预计从 ~620 行增至 ~800 行。

## 七、计算口径

```
覆盖率   cov    = Σ weight_i                       (前十大占净值比之和, %)
贡献     contrib = Σ (weight_i × return_i)          (return_i = 股票当日涨跌幅 f3, %)
估算涨幅 est%   = contrib / cov                      (放大到满仓; 等价 Σ(w_i/cov × r_i))
估算净值 gsz_est = NAV × (1 + est%/100)
```

- `SCALE_TO_FULL` 常量：`True`=口径 B（除以 cov），`False`=口径 A（不除，其余按 0）。默认 `True`。预留此开关，便于对比 240011 真实值后一行翻转口径。
- 今日收益复用现有：`(gsz_est − NAV) × num`。
- 持有额：`gsz_est × num`。
- 已结算判定不变：`PDATE == 今日` 即已结算，用 `NAVCHGRT`，不触发持仓估算。

## 八、数据源（均已实测可用，2026-07-29 盘中）

| 用途 | 端点 | 关键参数/字段 |
|---|---|---|
| 基金基础信息 | `https://fundmobapi.eastmoney.com/FundMNewApi/FundMNFInfo` | `plat=Android&appType=ttjj&product=EFund&Version=1`，`Fcodes` 批量 |
| 基金持仓 | `https://fundf10.eastmoney.com/FundArchivesDatas.aspx` | `type=jjcc&code=<code>&topline=10&year=<Y>&month=<M>`，返回 HTML；提取「股票代码(secid)+占净值比%」 |
| 股票行情 | `https://push2.eastmoney.com/api/qt/ulist.np/get` | `fltt=2&secids=<市场.代码,...>&fields=f12,f14,f2,f3`；`f3`=涨跌幅% |

- 股票 `secid` 市场前缀：持仓 HTML 里 `quote.eastmoney.com/unify/r/1.600519` 已带前缀（1=沪, 0=深），直接复用，无需自判市场。
- 持仓 HTML 的「最新价/涨跌幅」列为 JS 占位符（`<span data-id=...>`），静态取不到，故必须单独拉股票行情。
- 批量行情端点必须带 `fltt=2`，否则返回裸整数；字段编号 `ulist.np` 用 `f2/f3`（非 `f43/f170`）。

## 九、季报选择

季报有披露滞后：2 季报（截止 6-30）通常 8 月中才披露，7 月底可能尚未出。

逻辑：按当前月份倒推最近 4 个季报节点依次尝试，取首个返回非空且截止日最新者。端点 `month` 参数取**季度末月**（3 / 6 / 9 / 12，分别对应 Q1 / Q2 / Q3 / Q4 报告）。季度映射：

| 当前月份 | 候选最近季报截止日 |
|---|---|
| 1–3 | 去年 Q4（12-31） |
| 4–6 | Q1（3-31） |
| 7–9 | Q2（6-30），未披露则回退 Q1 |
| 10–12 | Q3（9-30） |

简化实现：生成最近 4 个候选 `(year, quarterEndMonth)`（quarterEndMonth ∈ {3,6,9,12}）依次请求，首个命中即用。

## 十、兜底降级

持仓估算失败时逐级回落，不报错中断：

```
持仓估算可用                 -> [自算]  gsz_est
否则跟踪指数,行情可查        -> [自算]  指数实时涨跌
否则跟踪指数无行情(字母指数) -> [自算]  母ETF行情推估 (2026-08-17 补充: LINKED_ETF_BY_INDEX 映射, 如 SPCLLHCP->515450)
否则接口有 GSZ              -> [估算]  接口盘中估值 (现有行为)
否则已结算                  -> ✓       NAVCHGRT 真实值
否则                        -> [无估值] -
```

触发降级场景：
- 持仓拉取失败 / 季报为空（新基金无季报）
- 股票行情失败
- 前十大覆盖率过低（`< MIN_COVERAGE`，视为不可信）
- 跟踪指数代码为境外非交易指数（标普系列等），东方财富行情无收录，且无母 ETF 映射

## 十一、展示标记

`item_for_fund` 的 `flag`：

| 状态 | 标记 |
|---|---|
| 持仓自算 | `[自算]` |
| 接口 GSZ | `[估算]`（保留现有） |
| 已结算 | `✓` |
| 无估值 | `[无估值]` |

合计行 `when` 前缀：盘中且有自算 -> `自算 @ <时间>`；否则维持现有 `估算/净值`。时间用股票行情时间戳。

## 十二、缓存

- 路径：`get_data_dir()/holdings_cache.json`
- 结构：`{code: {as_of: "2026-06-30", stocks: [{secid, name, weight}, ...], fetched_at: <ts>}}`
- 有效期：7 天（持仓是季报数据，季度才变）
- 新增 `fund refresh` 子命令：清空持仓缓存强制重拉
- 股票行情不缓存（实时）

## 十三、性能预算

- 基金基础信息：1 次批量请求（现有）
- 持仓：缓存命中 0 请求；miss 时每基金 1 次，`ThreadPoolExecutor` 并发
- 股票行情：1 次批量（所有重仓股跨基金去重后一次拉）
- 目标 < 2s 返回；缓存命中时接近现有速度

## 十四、配置与常量

`funds.json` 无需改动。以下为 `fund.py` 顶部常量，需要时再考虑提升为配置项：

| 常量 | 默认值 | 说明 |
|---|---|---|
| `SCALE_TO_FULL` | `True` | 口径 B；`False` 切口径 A |
| `MIN_COVERAGE` | `20` | 覆盖率低于此(%)视为不可信，降级 |
| `HOLDINGS_CACHE_DAYS` | `7` | 持仓缓存有效期 |

## 十五、测试

- **单元**：`estimate_gsz` 用 mock 持仓 + 行情，验证口径 A/B、覆盖率边界、空持仓降级
- **集成**：用 240011 实跑，对比用户观察到的真实估值校准口径（A vs B）
- **回归**：现有 `fund` / `fund N` / `fund sum` / `fund config` 行为不变

## 十六、局限性

- 前十大重仓股之外的 36% 净值（现金/债券/其他股票）靠缩放近似，对主动型会高估（用户基本不持此类）。
- 季报数据最多滞后 3 个月 + 披露期，期间调仓无法跟踪。
- 季度间调仓会致估算失真，缓存刷新不解决（数据源限制）。
